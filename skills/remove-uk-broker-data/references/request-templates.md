# Request templates

Replace bracketed fields only with facts confirmed for the current private case. Verify the controller, recipient and minimum matching identifiers first. These templates confer no send authority and do not establish that a record exists. Omit unnecessary DOB, phone, address, work details, documents and device identifiers.

## Marketing objection and applicable erasure

Subject: Data protection request — [name]

Dear [verified privacy team],

I object under Article 21 UK GDPR to processing of my personal data for direct marketing and related profiling. Please stop that use and disclosure, and erase the associated personal data where Article 17 applies.

Please locate existing records using [minimum necessary user-confirmed identifier or verified listing URL]. [If an address is needed: This is an associated matching address, not a statement of my current residence.]

Use these details only to handle this privacy request. Please retain only the minimum suppression information needed to honour my objection and prevent reintroduction, plus necessary request-handling records.

Please confirm the outcome and product/identifier scope. If you retain data for another purpose, explain the purpose, lawful basis and retention period. If proportionate verification is necessary, explain the minimum required before requesting documents.

Kind regards,
[name]

## Supplier identified by another controller

Add only when supported by actual correspondence:

On [date], [controller] identified your organisation as a source of the record associated with [minimum matching identifier]. I am contacting you about that source record. Please identify its original source and collection date, the basis on which you obtained and shared it, and relevant upstream/downstream recipients. If you relied on consent, please explain the consent record on which you relied. Where applicable, notify recipients of erased data as required by data protection law.

Do not forward the complete broker conversation or an identity document merely to establish this referral. Log the reported supply chain separately from any supplier-confirmed record.

## Technical-identifier guidance

Subject: Identifier guidance for a privacy request

Dear [verified privacy team],

Your rights route requires [identifier type]. Please explain an accessible way to obtain an existing identifier from [user-confirmed device/browser type], or how you handle a request when no identifier exists. I do not want to create a new identifier or enable extra tracking merely to make a request.

This is a guidance enquiry. It does not assert that you hold a record or identify the relevant device data. Please use the correspondence only to answer this privacy enquiry.

Kind regards,
[name]

## Follow-up on a pending request

Use only after checking the actual receipt, verification, processing window, response clock and any extension:

On [date] I sent [precise request scope], reference [non-secret reference]. Your last response on [date] said [accurate short summary]. Please confirm the outstanding action and the data/address/identifier scope covered. [If justified: Explain why the response remains incomplete.] Please avoid treating this follow-up as a duplicate initial submission.

Do not allege a missed deadline or file an automatic formal complaint from a monthly schedule without checking current evidence and authority.
